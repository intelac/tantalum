# 扩展功能时，什么时候改内核、怎么改

这页是规矩，不是教程。来由：让一个会话交活给另一个会话（subagent）的第一版为了不动内核，做成了一个普通工具，里面有一个线程每 0.2 秒去看对方好了没有，交活和汇报都冒充用户提问。功能能用，但重启会丢活、账里说不清话是谁说的，也挡住了后面的 Super-Agent。后来按这页的办法重做过一版（见最后的例子）。2026-11-17 这个功能整个去掉了，代码里已经没有；规矩照旧，例子留作这套办法怎么用的示范。

## 判断标准

**不是“改得越少越好”，而是“改完之后，转移表和账还能把这件事从头到尾说清楚”。**

新事件、新状态会让内核变复杂，这是真的代价。但需求真的要内核知道的时候，就该改内核。绕开内核省下的复杂度不会消失，它会变成内核外面的线程、旁表和补丁，更难测、重启就坏。

## 这件事要不要进内核

问四个问题，有一个答“是”，就进内核：

| # | 问题 | 答“是”意味着 |
|---|---|---|
| 1 | 一轮运行要不要因为它停下来等？ | 等待必须是账里的一个状态，不能是线程 |
| 2 | 服务器重启之后，它还要不要算数？ | 必须在账里，从账里能重新算出来 |
| 3 | 它会不会改变会话或运行接下来怎么走？ | 必须是一条事件，由事件推动 |
| 4 | 事后要不要说得清“是谁、因为什么”？ | 要有自己的事件类型，不能借用别的事件冒充 |

四个都答“否”，用插件点就够了：工具、钩子、上下文片段、插件工作、工具后处理、面板。

## 进内核时，按这个形状做

| 需求里的东西 | 在内核里是什么 |
|---|---|
| 外面发生了一件事（人说了话、别的会话交回了结果、定时到了、外部系统来了消息） | 一种**事件**。新的事就加新的事件类型，不给已有的事件加新含义；旧账的读法不变 |
| 运行要等一件事 | 一个**状态**。手上有进行中的命令的，用已有的“等命令结果”；等的是外面的事、手上什么都没有的，加一个新状态，重启时不打断（例：等用户回答、等会话回答） |
| 要让外面发生点什么（调模型、跑工具、给别的会话送东西、起定时器） | 一条**命令**，由服务器里的处理器执行，结果作为事件回来。处理器不留状态、不等待 |
| 影响别的会话 | 命令 → 处理器把一条事件送进**对方会话的账**。一步只改事件所在的那个会话 |
| 可能丢、可能重复的送达 | 送的东西带编号，**可以重发、收的一方按编号去重**。不假设“恰好送到一次” |
| 给模型看的话、要不要等、超没超限 | 内核里的纯计算，只看状态和事件。内核不读时钟（用事件的时间）、不读文件、不读别的会话 |

## 不许走的捷径

| 捷径 | 为什么不行 |
|---|---|
| 在工具或插件里循环去看别处的状态（轮询） | 等待不在账里；占线程；重启就丢 |
| 以用户的身份代发一条提问或回答 | 账里分不清是谁说的；记忆、审计都会认错 |
| 把“谁在等谁”“谁是谁的子会话”记在内存或旁表里 | 回放算不出来；两处会对不上 |
| 工具里直接往别的会话的入口提交 | 这个副作用不是内核发的命令，账里看不出它从哪来 |
| 为了不加状态，把“等外面的事”塞进“等命令结果” | 重启会把它当成进行中的命令打断 |

实在要走捷径（比如先验证想法），先把“违反哪一条、省了什么、以后要还什么”写出来，由负责人决定；完成时的汇报里也要写明。

## 改了内核要付的账

- 转移表新增的每一行都有内核的纯函数测试。
- 同一串事件喂两次，状态和命令逐个相同。
- 新的事件、命令、状态写进账能原样读回；和它无关的会话一个字也不多写；旧账照旧能读。
- 在每个可能出事的时间点重启一次，结果仍然正确。
- 全量回归，再用真实的旧账回放一遍。

## 例子：会话之间说话（已去掉的功能，只作示范）

一开始想的是“subagent”：父子层级、专门的事件、专门的状态。后来发现它和普通会话是同一种行为：有人对会话说一句话，会话跑一轮，把结果交回给说话的人。差别只有“谁说的”和“结果给谁”。按这个想，内核里要加的就很少：

| 需求 | 四个问题 | 内核里的形状 |
|---|---|---|
| 一个会话让另一个会话做事 | 3、4 是“是” | 一种事件“会话来话”（从处理器这边进来，不冒充提问），一种命令“送话”。来和回用同一种事件 |
| 这一轮里就要对方的结果 | 1、2 是“是” | 一个状态“等会话回答”，和“等用户回答”是一对：没有命令在跑、重启不打断、期限记绝对时刻 |
| 做完把结果交回去 | 3 | 运行的主人多一种“回某个会话的某句话”；这样的一轮结束时发“送话” |
| 不要一层套一层 | — | 话上带“转了几手”，为回别人的话而开的一轮不能再往下交。不记父子关系 |
| 进程死在“送话记了账、还没送到”之间，话不能丢 | 2 是“是” | 送出去的话记在送的会话的信箱里，对方收到回一条事件“送到了”才去掉；重启后还在的，由一条事件“重送”让内核照原编号再送；收的一方记着最近收到的编号，重复的只回确认 |

教训：先问“这是不是已有行为换了个说话的人”，再决定要不要加东西。人说的话只从入口进来，处理器送回来的都不是人说的，这一条线能回答大部分“算谁说的”的问题。
