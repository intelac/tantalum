# Implementation Log: Task 12

**Summary:** APIs for choosing models. GET /api/models (ModelController): routes with displayName, kind, cloud, status, error category and models (id, name, window, windowSource, maxTokens, vision, levels, defaultLevel, toolChanges, points for this user), plus default, mine (null/omitted when unusable) and percent; no base-url or key-variable names. Submissions accept "model" (ModelJson; steer ignores it); ChoiceCheck.problem → 400 before anything reaches the journal (route/model/level/missing level/tool changes/images); without a choice the image check uses the model the run would use (ChoiceCheck.fallback: session's → user's last → default, shared with ContextHandler). Intake passes the choice into UserPrompt/FollowUpSubmitted. GET /api/settings adds model; PUT /api/settings/model saves the user's last choice (400 when unusable). Session messages view adds model and toolChangesInHistory. TranscriptPass emits a modelChange item (route, model, effort) when the session's choice differs from the previous run's (effort-only too; first choice of an old session not). /api/config model fields already use the default choice (task 10). The no-choice image refusal now reads '当前选的模型不支持图片' (SubmitAttachmentsTest updated deliberately). Finding: in practice most sessions count as having tool changes because tools that are off at session start (e.g. local-workspace tools when no computer is connected) make initialTools smaller than the whole set — so Claude models without mid-session tool changes are greyed in such sessions, exactly per M11.
