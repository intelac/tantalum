# Implementation Log: Task 20

**Summary:** Added BrowsersIT (failsafe): real Chromium headless shell, a local test site, a real Egress, the shared UserBrowserIT.DRIVER_DATA driver directory, and the package-private Browsers constructor with a 500 ms idle sweep. It is skipped with the install command when Chromium is missing, and every case checks that no driver or Chromium child process is left. Cases: (2.1, 2.2) alice's cookie is not visible to bob and alice's tab is not in bob's browser_tabs; type and click by ref change the title; alice's second session shares the cookie but keeps its own current page. (2.3, 3.1) clicking or navigating to a Content-Disposition download gives "This URL starts a file download; downloads are not allowed."; the uniquely named file appears in neither java.io.tmpdir, the data/driver dirs nor ~/Downloads, and no new playwright-artifacts dir holds files; the screenshot lands only in alice's attachments as an ImageRef. (2.4) with idleClose 2 s the browser closes, its processes exit, and the next call reopens with no cookie and one tab. (2.5) with maxOpen 2 the third user gets the exact busy sentence and the first two keep working. (NFR Reliability, 2.8) killing alice's Chromium main process (the child of the node driver) gives Browsers.CRASHED, bob is unaffected, alice's next call reopens, and close() leaves no processes. (4.1, 4.2, 4.4) with block-private-network on, the loopback page is refused before any browser starts; with it off, the page opens, its <img> to the configured own port never reaches that port (hit counter 0), and the egress logs exactly "web egress blocked 127.0.0.1:<port> (own-port)" with no path. Found while writing it: after earlier navigations Playwright prefixes main-frame refs with a frame id (f2e2), so BrowserToolsIT's ref regex (e\d+ only) would flake depending on test order. Both ITs now accept (f\d+)?e\d+, matching BrowserTools' own validator. All 9 browser ITs (6+2+1) pass together in one JVM on this Mac.
